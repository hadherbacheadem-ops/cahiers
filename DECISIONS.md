# Décisions de conception

Journal des choix non tranchés par le cahier des charges « Évolution fondée sur la recherche en sciences cognitives », avec la raison. Chaque phase ajoute sa section.

## Phase 0 — État des lieux et socle de données

### État des lieux (avant la phase)

- **Données** : Dexie v2, tables `cahiers / chapitres / exercises / attempts / settings / supplements / mindmaps`, timestamps en epoch ms. Un exercice = 6 types (`flashcard, cloze, mcq, truefalse, match, order`), `difficulty` 1–3, `tags`, état SM-2 `{ease, interval, due, reps, lapses}`. Aucun lien exercice → passage de la fiche, aucun statut (tout est actif dès l'import), pas de file « à valider ».
- **Journal** : `attempts` existait (exercice, ts, juste/faux, note, mode, durée) mais **tous les modes modifiaient le planning**, Chrono et S'entraîner compris. Pas de confiance, pas d'annulation.
- **Planificateur** : SM-2 simplifié (`lib/srs.ts`) — un échec remet `interval` et `reps` à zéro, plancher d'ease 1,3 (« ease hell »).
- **Sessions** : Réviser = dues triées par échéance, plafond 50, sans entrelacement ni gestion des siblings ; S'entraîner = 30 au hasard, ratés re-proposés ; Chrono = feedback immédiat, pas différé. Pas d'undo, pas d'édition en session, pas de leech.
- **Génération** : prompt « exhaustif » mais sans extraction de points de cours, sans ancre, sans schéma JSON strict ; validation zod des types à l'import ; pas de linter, pas de dédoublonnage.
- **Rendu** : `.prose-fiche` = texte brut (`white-space: pre-wrap`). Ni markdown ni LaTeX. Fiches texte seul, pas d'images stockées.
- **Sauvegarde** : JSON `version 1|2`, import par `bulkPut` sans migration ; les `attempts` étaient ré-ajoutés à chaque import (doublons).
- Ni tests, ni dépôt git, pas de PWA.

### Décisions

1. **Noms internes conservés.** Le cahier des charges parle de `ficheId`, `statut`, `source`, `affecteLePlanning` ; le code existant utilise `chapitreId`, des identifiants anglais et des timestamps numériques. On garde la convention du code (anglais, epoch ms) pour ne pas créer deux vocabulaires : `ficheId` → `chapitreId`, `statut` → `status` (`pending | active | suspended | leech`), `source` de l'exercice → `origin` (`claude | manual | inverse_auto`, pour ne pas confondre avec `Chapitre.source`), `affecteLePlanning` → `affectsScheduling`, `confiance` → `confidence`. Les libellés visibles restent en français.
2. **`attempts` remplacé par `reviewLogs`** (et non conservé à côté) : une seule source de vérité pour les stats, l'undo et la migration FSRS. La table `attempts` est supprimée par la version 3 de Dexie après conversion de chaque ligne. Les lignes historiques reçoivent `affectsScheduling: true` — elles ont réellement déplacé le planning SM-2 à l'époque, et le rejeu du journal doit reproduire ce qui s'est passé.
3. **Notes → ratings** : `again/hard/good/easy` → 1/2/3/4 (échelle FSRS). Une ligne sans note lisible prend 3 si juste, 1 si faux.
4. **Identifiants du journal** : UUID (chaîne) plutôt que l'auto-incrément de `attempts`, pour que l'import d'une sauvegarde soit idempotent (`bulkPut` par id) — c'est ce qui corrige les doublons d'attempts à l'import.
5. **Versionnage de la sauvegarde** : champ `schemaVersion` (autoritaire) + `version` conservé pour les anciens lecteurs. `migrateBackup()` est une fonction pure (`lib/migrations.ts`) partagée par l'import JSON et testée ; elle refuse les fichiers d'un schéma plus récent et tolère les tableaux manquants. Les hooks `upgrade` de Dexie réutilisent les mêmes fonctions (`attemptToReviewLog`, `upgradeExercise`).
6. **Statuts appliqués dès maintenant** : `loadScopeExercises` et les compteurs « dus » ne considèrent que `status === 'active'`. Tous les exercices existants sont migrés en `active`, donc aucun changement visible ; la file « à valider » (phase 2) n'aura qu'à insérer en `pending`.
7. **S'entraîner et Chrono ne déplacent plus le planning** (`affectsScheduling: false`) dès cette phase : le champ existe dans le journal et y écrire `true` pour ces modes aurait été faux. C'est la règle 3.4 appliquée par anticipation ; l'option « affecter quand même le planning » viendra avec la phase 3.
8. **Points de cours** : table `points` (`id, chapitreId, cahierId, anchor ≤ 200 caractères, title, nature, order`). Les exercices existants ont `pointId: null` ; ils seront rattachés lors de la prochaine génération (phase 2) ou manuellement.
9. **Tests** : vitest + `fake-indexeddb` ; `createDb(name)` exporté pour ouvrir des bases jetables. La migration Dexie est testée en écrivant réellement une base au schéma v2 puis en l'ouvrant avec le schéma v3.
10. **Image occlusion** : différée (P2). Les fiches sont du texte seul, aucune image n'est stockée — à reconsidérer après la phase 9 (stockage d'images en Blob).
11. **Git** : dépôt initialisé à cette phase (le projet n'en avait pas). Un commit par phase.

## Phase 1 — FSRS

1. **Bibliothèque** : `ts-fsrs` 5.4 (FSRS-6, paramètres par défaut, pas d'optimiseur côté client). Un seul module lui parle (`lib/fsrs.ts`) ; le reste manipule `FsrsCard`, une copie sérialisable de `Card` (dates en epoch ms) stockée dans `exercise.fsrs`. Le champ SM-2 `srs` disparaît (schéma Dexie v4, sauvegarde `schemaVersion: 4`).
2. **Migration SM-2 → FSRS** : (a) si un journal existe pour l'exercice, on rejoue chaque réponse (`next()` en boucle, sans fuzz — même calcul que `reschedule()`, reproductible) pour obtenir stabilité, difficulté, reps, lapses, état ; (b) sinon, conversion approximative documentée dans `fromSm2` : stabilité ≈ intervalle SM-2 (plancher 0,1 j), difficulté = 5 + (2,5 − ease) × 4,17 bornée à 1–10, état Review (Relearning si l'échec SM-2 était en cours, New si jamais vu). **Dans les deux cas la date d'échéance SM-2 est conservée** : rien ne devient dû ni reporté par le changement d'algorithme (transition graduelle, comme Anki).
3. **Paramètres exposés** : rétention visée 0,80–0,95 (défaut 0,90, curseur avec estimation « ≈ N révisions/jour » = Σ 1/intervalle_suivant(S, r) sur les cartes en état Review), intervalle maximal (défaut 365 j), nouveaux/jour (20), révisions max/jour (200, par cahier avec surcharge dans « Modifier le cahier »), jours légers, seuil leech (8, utilisé en phase 3), demande de confiance (phase 5). Fixés dans le code : `enable_fuzz: true`, `learning_steps ['1m','10m']`, `relearning_steps ['10m']`.
4. **Notes → ratings** pour les types auto-corrigés : faux → Encore, juste → Bien, « facile » explicite → Facile. « Juste avec indice → Difficile » attend un indice utilisable en session (aucun joueur n'en montre avant la réponse aujourd'hui) — à appliquer avec les nouveaux types (phase 3).
5. **Undo** : chaque `ReviewLog` porte `fsrsLog = { prev, next, log }`. Annuler restaure `prev` tel quel et supprime le journal — exact par construction ; un test vérifie que `rollback()` de ts-fsrs donne le même état mémoire. Raccourci `Ctrl+Z` et bouton dans l'en-tête de session ; l'annulation retire aussi la copie remise en fin de file après un « Encore ».
6. **File de révision et limites** : cartes en apprentissage d'abord (toujours servies, hors limites), puis cartes Review dues par échéance (plafond révisions/jour), puis nouvelles par date de création (plafond nouveaux/jour). Les compteurs du jour se lisent dans le journal (état de la carte *avant* la réponse : New → nouveau, Review → révision). Le plafond par cahier s'applique aussi en scope « tous les cahiers ». L'ancien plafond fixe de 50 disparaît. Le tableau de bord affiche ce que la session contiendrait réellement (« 37 dus · ~12 min », temps = médiane des durées du journal, 20 s par défaut).
7. **Jours légers** : après calcul FSRS, si l'échéance tombe un jour léger et que l'intervalle est ≥ 3 jours, on décale de ±1 puis ±2, ±3 jours (plus tôt d'abord : c'est la rétention qui perd le moins), jamais avant demain. L'état mémoire n'est pas touché. Les échéances déjà fixées ne bougent pas.
8. **Reporter / Avancer** (menu « … » du cahier) : reporter = cartes dues en état Review triées par récupérabilité décroissante, décalées de max(1 j, 5 % de l'intervalle) — règle du helper FSRS d'Anki ; avancer = cartes non dues triées par récupérabilité croissante, rendues dues maintenant. Seul `due` change ; l'impact affiché = probabilité de rappel moyenne avant/après.
9. **Modes hors planning** : S'entraîner et Chrono ne passent pas par FSRS (`affectsScheduling: false`), l'écran de fin le rappelle. Les réponses « Encore » en S'entraîner re-proposent l'exercice en fin de session sans le replanifier.
10. **Export du journal** : CSV au format fsrs4anki (`card_id, review_time, review_rating, review_state, review_duration`), uniquement les réponses ayant affecté le planning ; `review_state` = état avant la réponse (0 pour les lignes SM-2 sans détail).

## Phase 2 — Rendu, génération de qualité, validation, couverture

1. **Rendu** : `marked` (GFM, `breaks: true` pour que les retours à la ligne des textes collés survivent) + **KaTeX** (`$…$`, `$$…$$`, `\(…\)`, `\[…\]`, `\$` littéral, extension mhchem) + DOMPurify. Les formules sont extraites *avant* markdown (sinon `_` et `*` des formules sont interprétés) et réinjectées après. Un seul composant `<Markdown>` (bloc ou `inline`) utilisé dans les fiches, compléments, joueurs, résultats, cartes d'exercice, validation. **Cartes mentales** : texte SVG brut, le LaTeX y reste tel quel (P2 : foreignObject casserait l'export PNG).
2. **Prompt à deux temps, une seule réponse JSON** : étape 1 = liste des points de cours (`id`, `title`, `nature`, `anchor` = citation exacte ≤ 200 caractères), étape 2 = 1 à 3 exercices par point avec `pointId`. Schéma inclus dans le prompt. Règles d'écriture reprises telles quelles de la spécification 3.6 (un fait par exercice, questions autonomes, un seul trou, distracteurs compétitifs avec `distractorReasons`, `correctedStatement` obligatoire en V/F, LaTeX). Les types `demonstration` et `rappel_libre` n'entrent dans le prompt qu'avec leurs joueurs (phase 3).
3. **Génération ciblée** (`focus`) : le même prompt peut recevoir des points existants (ids réels réutilisés) et/ou des passages sans point (points créés). Utilisé par la vue couverture et par « Générer les exercices de ce complément ».
4. **Parseur** : zod ; `pointId` local ou réel ; alias `enonceCorrige` accepté ; un exercice sans `pointId` mais avec `anchor` identique à celle d'un point y est rattaché. À l'import, un point dont l'ancre existe déjà dans la fiche est réutilisé plutôt que dupliqué.
5. **Linter déterministe** (`lib/lint.ts`) : réponse > 25 mots, double question (deux interrogatifs reliés par « et », ou deux « ? »), énumération (« cite / énumère / quels sont… »), pronom initial, trou sur mot-outil, réponse visible dans la phrase, plusieurs trous (info), choix QCM > 2× la médiane, bonne réponse toujours à la même position (≥ 3 QCM du lot), distracteurs non justifiés (info), V/F sans énoncé corrigé, LaTeX déséquilibré, ancre introuvable (points), quasi-doublon. Test : 10 défauts semés → 10 détectés (critère ≥ 9).
6. **Dédoublonnage** : trigrammes de caractères sur texte normalisé (minuscules, sans accents ni ponctuation), coefficient de Dice, seuil 0,8, contre les exercices existants de la fiche et les éléments précédents du lot. Signalé, jamais supprimé.
7. **File « à valider »** : les exercices générés arrivent en `status: 'pending'` (hors planning) et la page `/…/valider` les présente un par un avec les défauts (J garder, K ignorer, E modifier, Ctrl+A tout garder). Réglage « Toujours tout garder sans valider » (`autoValidate`) pour activer directement. La liste des exercices d'une fiche montre un badge « À valider » et une bannière avec le compte.
8. **Couverture** : la fiche est découpée en blocs (paragraphes, puces ; les titres seuls ne comptent pas, les tableaux sont ignorés, blocs < 4 mots ignorés). Un bloc est ancré si l'ancre d'un point le recouvre (inclusion normalisée, ou fenêtre de 30 caractères pour une citation partielle). Affichés : points sans exercice actif/en attente, blocs sans point, pourcentage ancré, bouton « Générer pour ces points ».
9. **Compléments** : les compléments gardés restent listés avec « Générer les exercices de ce complément » (génération ciblée sur le texte du complément).
10. **Édition** : modal d'édition par type (choix/bonnes réponses/raisons pour les QCM, énoncé corrigé pour les V/F, paires « terme | définition », etc.), aperçu rendu et linter en direct ; accessible depuis la validation (E) et la carte d'exercice. Suspendre / réactiver depuis la carte.

## Phase 3 — Nouveaux types, sessions, leeches

1. **Rappel libre guidé** (`rappel_libre`) : un seul par fiche, généré avec une `checklist` de 5 à 15 notions (chaque item peut porter le `pointId` de son point de cours, mappé à l'import). Joueur en deux temps : écriture libre (chrono affiché, Ctrl+Entrée), puis cases à cocher « ce que tu avais écrit » + case « sans hésitation » (activée seulement si tout est coché). Note : < 50 % Encore, 50–80 % Difficile, ≥ 80 % Bien, 100 % sans hésitation Facile. Les notions non cochées relancent leurs exercices : ceux du même `pointId`, actifs et non dus, deviennent dus immédiatement (compte affiché dans le résumé).
2. **Démonstration / méthode** (`demonstration`) : `steps[{text, why}]`, `statement`, `title`. Estompage stocké sur l'exercice (`fading: {level, streak}`) : niveau 1 = une étape masquée (choisie par un hachage id + reps, donc différente à chaque révision), niveau 2 = une étape sur deux, niveau 3 = énoncé seul avec zone de reconstitution puis comparaison. Auto-noté 1–4 après révélation ; deux réussites consécutives montent d'un niveau, « Encore » redescend, « Difficile » remet la série à zéro. « Pourquoi ? » est un bouton facultatif par étape, jamais imposé (Barbieri 2023).
3. **Vrai/Faux + correction** : choisir « Faux » exige d'écrire l'énoncé corrigé avant la révélation (quand `correctedStatement` existe). Le verdict est auto-corrigé ; une correction juste mais éloignée de l'attendu (Dice < 0,45 sur trigrammes) est notée « Difficile » et signalée. Le prompt n'émet plus de V/F sans `correctedStatement`.
4. **Entrelacement** (`lib/interleave.ts`) : la file Réviser (après limites) est réordonnée gloutonnement — jamais deux exercices du même point à la suite (pénalité −100), fiche différente +2, type différent +1, ordre d'échéance en départage ; cartes en apprentissage d'abord. Cahiers marqués « vocabulaire / lexique » (`Cahier.lexical`, case dans « Modifier le cahier ») : bloc par fiche, ordre d'échéance, en fin de file. Test : session mixte sur deux fiches sans siblings adjacents.
5. **Siblings enterrés** : après une réponse en Réviser (réglage `burySiblings`, défaut oui), les autres exercices actifs du même point, dus et pas en apprentissage, passent à demain 0 h et sortent de la file courante. Comptés dans le résumé.
6. **Feedback** : immédiat en Réviser et S'entraîner ; **différé en Chrono** (`deferFeedback` : les joueurs répondent sans verdict, l'écran de fin liste chaque question avec juste/faux, réponse attendue, énoncé corrigé, explication). Jamais absent.
7. **Leeches** : au moment où une réponse « Encore » porte `lapses` au seuil (`leechThreshold`, défaut 8), l'exercice passe en `leech` (hors planning) et une fenêtre propose *Réécrire avec Claude* (prompt « principe d'information minimale », 1 à 3 exercices atomiques importés en `pending`, le leech est suspendu pour garder son historique), *Suspendre* ou *Continuer*. Test : leech déclenché au 8ᵉ échec.
8. **Session** : `E` ouvre l'éditeur sur l'exercice courant (la file recharge la copie modifiée), `-` enterre l'exercice à demain sans répondre (Réviser), `@` le suspend (confirmation), `?` affiche l'aide des raccourcis, `Ctrl+Z` annule. Résumé : réussite, temps, exercices reportés, exercices relancés, prochain rappel de la sélection, « À retravailler » (hors Chrono, qui affiche la correction complète à la place).
9. **« Juste avec indice → Difficile »** : aucun joueur ne montre d'indice avant la réponse (les flashcards affichent l'indice avec la réponse) ; la règle reste inappliquée, documentée ici.

## Phase 4 — Préparation d'examen

1. **Stockage** : les examens vivent sur le cahier (`Cahier.examens[]`, comme le suggère la spécification) : `name`, `date` (minuit local du jour J), `chapitreIds`, `boostFromDays` (défaut 14), `sessions[3]` (`at`, `done?`), `archived`. Pas de table dédiée : quelques examens par cahier, lus avec le cahier.
2. **Plan de réapprentissage successif** : trois séances qui se terminent la veille de l'examen, avec des écarts qui se resserrent (Cepeda : l'écart optimal est une fraction du délai restant) : S3 = J−1, S2 = S3 − max(1, 25 % du délai), S1 = S2 − max(1, 30 % du délai). Pour 21 jours : J−12, J−6, J−1 (l'exemple de la spécification). Jamais avant aujourd'hui ; jours dédoublonnés quand le délai est court. Changer la date replanifie en conservant les séances déjà faites.
3. **Séance d'examen** (`mode=exam&session=i`) : tous les exercices actifs des fiches de l'examen, entrelacés ; chaque échec remet l'exercice en fin de file jusqu'à un rappel correct ; la séance est cochée à la fin. Ces réponses **affectent le planning** (`affectsScheduling: true`) : ce sont de vraies récupérations avec feedback, FSRS doit en tenir compte — contrairement au cramming.
4. **Surcharges du planificateur** : pour chaque fiche d'un examen à venir, `maximum_interval` = min(global, ⌊jours restants / 2⌋, ≥ 1) et rétention visée 0,95 à partir de `boostFromDays` avant l'examen. Un planificateur ts-fsrs par couple (rétention, intervalle max) est mis en cache dans le contexte de session (`schedulerFor(exercise)`), utilisé pour les réponses, les intervalles affichés et l'ordre du cramming. Quand plusieurs examens couvrent une fiche, le plus strict gagne. Nuance : ts-fsrs impose Difficile < Bien < Facile strictement, si bien qu'un « Bien » ou un « Facile » peut dépasser le plafond d'un ou deux jours.
5. **Cramming** (« Réviser tout maintenant ») : tous les exercices actifs des fiches de l'examen triés par récupérabilité croissante, feedback immédiat, `affectsScheduling: false` — aucune échéance ne bouge (test). Le résumé le rappelle.
6. **Après l'examen** : les surcharges cessent automatiquement dès que la date est passée (calculées à chaque chargement) ; l'examen reste affiché avec un message et un bouton « Archiver » qui le masque — c'est le « proposer de ramener la rétention au réglage global » de la spécification, sans action irréversible.
7. **Tableau de bord** : jusqu'à trois examens à venir avec compte à rebours, jauge des séances et bouton vers la prochaine séance (« en retard » si sa date est passée).

## Phase 5 — Confiance, calibration, statistiques, série

1. **Confiance avant la réponse** : sélecteur Sûr / Hésitant / Aucune idée (S, H, A) affiché *avant* la révélation sur les flashcards, démonstrations et textes à trous (Nelson & Dunlosky : un jugement après lecture est sans valeur). Facultatif (on peut révéler sans choisir), désactivable (`askConfidence`), jamais en Chrono. Stocké dans `ReviewLog.confidence`.
2. **Hypercorrection** : une erreur donnée avec « sûr » en mode planifié ajoute `forcedDue = [J+1, J+7]` (minuit local) sur l'exercice ; à chaque réponse, les dates passées sont retirées et la prochaine échéance FSRS est plafonnée par la première date restante. Le pas de réapprentissage (minutes) reste prioritaire quand il est plus proche. Le résumé de session compte ces erreurs.
3. **Calibration** : par niveau de confiance, réponses et taux de réussite sur 90 jours ; avertissement quand « sûr » réussit sous 85 % avec au moins 10 réponses (avant, pas de verdict : trop peu de données).
4. **Statistiques** (`/stats`), toutes recalculées depuis le journal + les exercices (`lib/stats.ts`, testé) : *true retention* = réussite des réponses planifiées sur des cartes déjà en état Review (ni apprentissage, ni nouvelles, ni entraînement libre) sur 7/30/90 jours et par cahier ; prévision de charge à 30 jours (retard cumulé sur aujourd'hui) ; heatmap 365 jours ; réussite par heure (réponses planifiées) ; rétention estimée = moyenne des récupérabilités des cartes actives non nouvelles, avec le planificateur de chaque fiche (surcharges d'examen incluses).
5. **Série bienveillante** : un jour compte s'il atteint l'*objectif minimal* (`minimalGoal`, défaut 10 réponses, tous modes), distinct de l'*objectif du jour* (`dailyGoal`, indicatif) ; jusqu'à 2 jours manqués par mois civil sont « gelés » automatiquement sans casser la série ; aujourd'hui ne casse jamais la série ; à 0 le tableau de bord dit « prêt à commencer », jamais « série perdue ». Remplace l'ancienne série stricte (`computeStreak`).

## Phase 6 — Carte mentale à trous, saisie, cartes inverses

1. **Exercices de carte mentale** : à l'enregistrement d'une carte de fiche, deux exercices `carte_trous` sont créés (variantes `trous` et `reconstruction`, actifs, sans point de cours) ; ils suivent le planning FSRS comme les autres et sont supprimés avec la carte. Les cartes de synthèse d'un cahier (sans fiche) n'en ont pas : ce sont des vues d'ensemble. La page de la carte reste consultable mais dit explicitement que lire n'est pas réviser et renvoie vers l'entraînement.
2. **Rendu du joueur** : la carte est jouée sous forme de *plan indenté* (une ligne par nœud, pastille de couleur par branche), pas dans le SVG : le masquage et la saisie y sont plus simples et accessibles au clavier, et la structure reste lisible. Le rendu SVG masqué est possible plus tard.
3. **Masquage** : 30–50 % des nœuds non racine, choix déterministe à partir de l'id de l'exercice et du nombre de révisions (le masque change à chaque passage), au moins un nœud visible par branche. Verdict Su / Raté par nœud révélé ; note par ratio comme le rappel libre. Reconstruction : racine et branches de niveau 1 visibles, sous-nœuds saisis de mémoire par branche, puis comparaison par cases à cocher.
4. **Saisie de la réponse** : `typed` sur une flashcard (Claude le pose pour les formules et valeurs exactes ; réglage « toujours saisir » pour tout) ; comparaison Dice sur texte normalisé ou sur LaTeX normalisé (délimiteurs, `\left/\right`, espaces fines, accolades simples, `\frac` → `(a)/(b)`, `\cdot` → `*`), seuil 0,85 pour proposer « Bien », sinon « Encore » proposé ; diff mot à mot affiché ; l'élève tranche toujours (les quatre boutons restent disponibles, le bouton suggéré est mis en avant). L'ordre des facteurs commutatifs n'est pas normalisé (aide, pas juge).
5. **Cartes inverses** : à l'import (réglage `autoInverse`, défaut oui), chaque flashcard d'un point de nature `definition` ou `formule` dont la réponse fait ≤ 12 mots produit sa carte inverse (question ↔ réponse, `inverse: true`, `origin: 'inverse_auto'`, même point, même statut d'import donc « à valider »). Une seule inverse par réponse identique. Le prompt demande à Claude de ne plus les écrire lui-même.

## Phase 7 — Persistance et portabilité

1. **PWA** : `vite-plugin-pwa` (`registerType: 'autoUpdate'`), manifest en français, icônes SVG (`sizes: any`, acceptées par Chromium pour l'installation ; pas d'outil de rasterisation dans le projet), précache Workbox élargi aux `.woff2` et `.wasm` (KaTeX, sql.js) avec un plafond de 6 Mo par fichier.
2. **Persistance** : `navigator.storage.persist()` est demandé à la création du premier cahier (dès qu'il y a quelque chose à perdre) et depuis les réglages ; l'état (`persisted()`, usage / quota) est affiché. Safari est détecté par l'agent utilisateur pour afficher l'avertissement des 7 jours.
3. **Sauvegarde automatique** : File System Access API (Chrome / Edge) ; le `FileSystemFileHandle` est stocké dans une nouvelle table `kv` (schéma Dexie v5) avec l'état (nom, dernière écriture, erreur). Déclenchement par `Dexie.on('storagemutated')` (toutes les écritures, cet onglet ou un autre) avec un délai de 2,5 s, en ignorant les écritures dans `kv` elle-même. Après un rechargement, l'autorisation d'écriture redevient « prompt » : un bouton « Reprendre » la redemande (geste utilisateur obligatoire). Hors Chromium : export manuel.
4. **Conflits à la restauration** : si la base contient des modifications plus récentes que `exportedAt` du fichier, une confirmation explique que la fusion fera reprendre leur ancienne version aux éléments présents dans le fichier.
5. **Export Anki** : `.apkg` écrit sans bibliothèque tierce dédiée — sql.js (SQLite en wasm) + JSZip, schéma legacy v11 comme genanki (`genanki-js` est pensé pour des balises `<script>` globales et n'est pas maintenu côté npm). Notetypes « Cahiers Basic » et « Cahiers Cloze », un paquet par fiche (`Cahiers::Matière::Fiche`), GUID déterministe par exercice (ré-export = mise à jour), LaTeX converti en `\(…\)`. L'historique FSRS n'est pas transféré. Vérifié par relecture du fichier produit dans les tests, pas par import dans Anki desktop.
6. **CSV / TSV** : recto, verso, type, tags, fiche, cahier, statut.

## Phase 8 (optionnelle) — QCM pondéré, pré-test

1. **QCM pondéré par la confiance** : réglage `weightedMcq`, désactivé par défaut (une seule étude, Sparck 2016). Sur un QCM à réponse unique hors Chrono : premier choix = réponse principale, second choix facultatif = alternative, curseur 50–95 % ; score = confiance placée sur la bonne réponse (1 si un seul choix juste, 0 si aucune des deux) ; note : ≥ 75 % Bien, ≥ 50 % Difficile, sinon Encore ; le score est affiché dans le feedback. Jamais de note de confiance après la révélation (inefficace).
2. **Pré-test** : menu « … » du cahier → « Pré-test d'un chapitre » : Claude génère 3 à 5 questions conceptuelles à réponse courte à partir du programme (ou du programme standard du niveau) ; l'élève répond sans notation, les réponses attendues n'apparaissent qu'à la fin. Les questions sont mémorisées (`kv`, une par cahier) et, à la prochaine génération d'exercices dans ce cahier, une case cochée par défaut les ajoute comme passages à couvrir (seuls les items pré-testés profitent de l'effet, g ≈ 0,54 contre 0,04 pour le reste), puis le pré-test est effacé.
3. **Occlusion d'image** : non implémentée — les fiches restent du texte, aucune image n'est stockée (voir phase 0). À reconsidérer avec le stockage d'images.

### 1. Saisie de formules
- `isFormula(réponse)` : délimiteurs `$`, `\(`, `\[`, commande LaTeX, ou symboles au moins aussi nombreux que les lettres (E = mc^2, 9,81 m/s²).
- Formule : « Bien » suggéré uniquement en cas d'égalité exacte après normalisation ; sinon aucune suggestion (quatre boutons au même niveau, aucun focus imposé) et un diff caractère par caractère sur le LaTeX normalisé (ajouts barrés en rouge, manques en vert). Le score Dice n'est plus qu'informatif pour les formules.
- Texte : ≥ 0,85 → « Bien » suggéré ; 0,6–0,85 → aucune suggestion (message « à toi de juger ») ; < 0,6 → « Encore » suggéré.
- Normalisation LaTeX complétée : `\displaystyle`/`\textstyle`, `\,` `\;` `\!` `\:`, `\dfrac`/`\tfrac` → `\frac` (désormais **avant** la réécriture de `\frac`, ce qui était un ordre de règles fautif), `\times` → `\cdot`, `^{x}` → `^x` et `{x}` → `x` pour un seul caractère hors nom de commande. L'ordre des facteurs n'est pas normalisé.
- Tests : `E = -mc^2` contre `E = mc^2` → aucune suggestion, diff sur le signe ; `\frac{1}{2}mv^2` contre `\dfrac{1}{2} m v^{2}` → exact ; `x^2` contre `x^3` → diff sur l'exposant ; une formule longue à un signe près dépasse 0,85 de similarité et n'est pourtant pas suggérée.
